# RAID PANEL

Twitchでレイドを受けたときに、相手の情報とリンクを配信主だけに出すツールです。
公式シャウトアウトも自動で飛ばします。

配信画面には出ません。OBSに映していない限り、視聴者からは見えない作りになっています。

- 公開URL: https://naruseaoivt.github.io/raid-panel/
- リポジトリ: NaruseAoiVT/raid-panel（Public / GitHub Pages）
- Twitchアプリ: MEDISIA RAID PANEL（公開クライアント / Broadcaster Suite）

## 2つの版があります

中身は同じで、置き場所だけが違います。

| 版 | 開き方 | 向いている場面 |
|---|---|---|
| ブラウザ版 `index.html` | Chromeなどでサブモニタに開く | 画面が余っている環境 |
| OBSドック版 `dock.html` | OBSのカスタムブラウザドックに入れる | モニタが1枚しかない環境 |

**どちらか一方だけを開いてください。**
両方を同時に開くと、送信の待ち時間をそれぞれが別に数えます。
結果としてシャウトアウトが二重に飛んでしまいます。

## OBSドックへの入れ方

STEP 01 OBSの「表示」→「ドック」→「カスタムブラウザドック」を開きましょう。

STEP 02 ドック名に `RAID PANEL`、URLに下記を貼ります。

```
https://naruseaoivt.github.io/raid-panel/dock.html
```

STEP 03 「適用」を押すとパネルが出てきますので、好きな位置にドラッグしてください。

STEP 04 自分のTwitch ID（英数字のほう）を入れて、「RAIDチェッカーを起動」を押しましょう。

STEP 05 ログインは引き継ぎがおすすめです。次の項目へ。

### ログインの引き継ぎ

OBSのドックは、Chromeとは別のブラウザ扱いになります。
ですのでChromeでログイン済みでも、ドック側は未ログインのまま。
小さなパネルでIDとパスワードを打つのは大変ですよね…

そこでブラウザ版に引き継ぎの口を作りました。

1. ブラウザ版の「OBSドックに渡す／うまくログインできないとき」を開く
2. 「OBSドック用の引き継ぎコードをコピー」を押す
3. ドック側の同じ欄に貼り付ける

これでログインがそのまま移ります。
なおこのコードはログインそのものですので、人には渡さないでください。

### ドック版だけの挙動

- 通知音は既定で切ってあります。OBSがデスクトップ音声を拾っていると、音が配信に乗るためです
- 「相手の配信を開く」はURLのコピーを兼ねます。ドック内から外部ブラウザを開けない環境があるためです
- 音・通知・配色はブラウザ版と別に覚えます。共有されるのはログイン・チャンネル・履歴・送信制限のほう

実際の通信をせずに毎回同じ状態が撮れます。

```

"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --force-device-scale-factor=2 --window-size=1600,900 \
  --screenshot=out.png http://127.0.0.1:8795/_shot/01-setup.html
```

画像に出てくる「サンプル配信者」は撮影用の架空の相手です。
実際のレイドが来たときに撮り直すと、より伝わる画になります。

## 見た目

下敷きにしたのは Apple のスタイルリファレンスです。
白の余白を広く取り、書体で階層を作り、影を使いません。
強調色だけMEDISIAのピンクに差し替えてあります。

色の役割は1つに固定しました。

| 色 | 役割 |
|---|---|
| `#FF0066` | 塗りボタンと、点灯中のランプ。文字色や枠線には使いません |
| `#CC0052` | 枠線ボタン・リンク・エラー文字 |
| `#1d1d1f` | 本文 |
| `#f5f5f7` | 面の色。白のページから一段だけ沈めるために使います |
| `#d2d2d7` | ヘアライン |

ここで1つ注意があります。
白文字を `#FF0066` に乗せると、コントラストが 3.86:1 にしかなりません。
通常の文字に必要な 4.5:1 を下回ってしまう数字です。

ですので**塗りボタンの文字は19px / 太さ600に固定**しました。
この大きさなら基準が 3:1 に下がりますので、そこは満たせます。
小さくすると割ってしまいますから、詰めたくなっても触らないでください。
文字や枠線に使う `#CC0052` のほうは、白地で 5.69:1。こちらは余裕があります。

影は使いません。階層は面の色とヘアラインで作ります。
例外はレイド主のアイコン1つだけ。白地に浮かせるための影を許してあります。

配色は「ライト」と「ダーク」の2つ。既定はライトです。
OBSのドックは暗いアプリの中に置かれますので、眩しい方はダークへ。

## ログインしたあと

事故を防ぐため、ログインすると画面が切り替わります。

- ヘッダーと接続欄に、ログイン中のアカウントのアイコンと表示名が出ます
- チャンネル欄はグレーに変わり、もう触れません
- 中身はログインしたアカウント本人に固定。違う値が入っていたら書き換えます

チャンネルを固定するのは、シャウトアウトの送り主がログインしたアカウントだからです。
別のチャンネルを見たままだと、レイドは画面に出るのに送信だけ失敗します。
気づきにくい壊れ方ですので、そもそも選べないようにしました。

右下には作者のクレジットを小さく置いてあります。押すとXへ飛びます。

## 仕組み

### レイドの検出は二重にしてあります

1つめは匿名IRC。`wss://irc-ws.chat.twitch.tv:443` に `justinfan` でつなぎます。
ログイン名・表示名・人数・ユーザーIDは、すべて `USERNOTICE` の `msg-id=raid` タグの中。
認証が要らないので、ログイン前でも検出とリンク表示だけは動きます。

2つめはEventSub WebSocketの `channel.raid`。ログイン後に購読します。スコープは不要です。

同じレイドが両方から届きますので、`login|viewers` をキーに20秒の窓で重複を落としています。
片方が落ちても、もう片方が拾ってくれます。

### シャウトアウトは待ち時間を先読みします

叩くのは `POST /helix/chat/shoutouts`。スコープは `moderator:manage:shoutouts` です。

Twitch側には3つの制限があります。

- 全体で2分に1回
- 同じ相手には60分に1回
- 自分が配信中でないと送れない

送信時刻をlocalStorageに残し、送れない間はキューに積みます。
カウントダウンを出しながら順番に送りますので、連続レイドでも取りこぼしません。
429が返った場合も、キューに戻して再試行します。

### 認証はOAuth Implicit Grantです

リダイレクト先は `location.origin + location.pathname` が既定。
GitHub PagesのURLをそのままTwitchアプリに登録すれば動きます。
`file://` で開いた場合はログインできませんので、トークンの手貼りも別に用意しました。

## 記録の残りかた

パネルの履歴はlocalStorageに最大500件。日付で区切って並び、CSVにも書き出せます。

ただし、レイドの本記録を持っているのは `~/Desktop/did-stream-bot` のほうです。
Cloudflare Workers + D1 が、EventSubで全メンバー分を受けています。

スプレッドシート「MEDISIA 配信データ」の**レイド記録タブ**をご覧ください。
直前同接・5/15/30分後の同接・定着人数まで並びます。
パネルを開いていない配信のレイドも、そちらには入ります。

EXPORT_KEYはパネルに持たせていません。
GitHub Pagesは誰でも読めますので、鍵を埋めると全メンバーの配信データが公開されてしまいます。

## 制約

- ページを閉じるとチェッカーも止まります。常駐はしません
- Implicit Grantのトークンは約60日で切れます。切れたら押し直すだけです
- ログインしない場合、相手の配信タイトル・カテゴリ・アイコンは出ません
- 公式シャウトアウトは、自分が配信中でないとAPIが400を返します

## つまずいたところの記録

同じ罠を踏まないよう、直した内容を残しておきます。

**接続のつなぎ直しが止まらなくなりました。**
古い接続を閉じるとき、後始末の処理を外していなかったのが原因です。
外さずに閉じると「切れたからつなぎ直す」が走り、
たった今作った新しい接続まで巻き込んで永久に繰り返します。
`closeSocket` を通して閉じる形に直し、`test.mjs` で見張っています。

**レイドの向きを取り違えていました**（配信データ基盤の側）。
レイドの通知は送り手と受け手で本文が同じですので、
どちらの購読で届いたかは `subscription.condition` を見るしかありません。
イベント本文だけで判定していたため、送ったレイドが
「相手が受けたレイド」として記録されていました。

# RAID PANEL

Twitchでレイドを受けたときに、**配信主だけが見る画面**に相手の情報とリンクを出し、
**公式シャウトアウトを自動送信**するブラウザツール。サーバー不要・単一HTML。

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` | 本体。CSS/JSインライン。これ単体で動く |
| `config.js` | Client ID などの設定。ここだけ編集する |
| `セットアップ_作者用.txt` | 鳴瀬碧衣が1回だけ行うホスティング手順 + ライバーへの案内文テンプレ |
| `つかいかた_ライバー用.txt` | 配布用の説明書 |

## 設計

**レイド検出は二重化**している。

1. **匿名IRC**（`wss://irc-ws.chat.twitch.tv:443` に `justinfan` で接続）
   `USERNOTICE` の `msg-id=raid` タグからログイン名・表示名・人数・ユーザーIDを取得。
   **認証不要**なので、ログイン前でも検出とリンク表示だけは動く。
2. **EventSub WebSocket**（`channel.raid`）
   ログイン後に購読。スコープ不要。

両方から同じレイドが届くため、`login|viewers` をキーに20秒窓で重複除去している。
片方が落ちてももう片方で拾えるのが二重化の目的。

**シャウトアウトは `POST /helix/chat/shoutouts`**（スコープ `moderator:manage:shoutouts`）。
Twitch側の制限（全体2分に1回／同一相手60分に1回／配信中のみ）を
localStorage上のタイムスタンプで先読みし、送れない間はキューに積んで
カウントダウンを出しながら順番に送る。429を受けた場合もキューに戻して再試行する。

**認証は OAuth Implicit Grant。**
リダイレクト先は `location.origin + location.pathname` を既定にしているので、
GitHub Pages の URL をそのままTwitchアプリに登録すればよい。
`file://` で開かれた場合はログインできないため、トークン手貼りの
フォールバックを「上級者向け」として折りたたみで用意している。

## 記録

パネル自身の履歴は localStorage に最大500件。日付区切りで表示し、CSV書き出しができる。
**恒久的な記録はここではない。** レイドの本記録は `~/Desktop/did-stream-bot`（Cloudflare Workers + D1）が
EventSubで全メンバー分を受けており、スプレッドシート「MEDISIA 配信データ」の
**レイド記録タブ**に、直前同接・5/15/30分後の同接・定着人数まで出る。
パネルを開いていない配信のレイドもそちらには入る。

EXPORT_KEY をこのパネルに持たせない。GitHub Pages は誰でも読めるため、
鍵を埋めると全メンバーの配信データが公開されてしまう。

## 制約（設計上わかっていること）

- ページを閉じると監視は止まる。常駐はしない（サーバーレスの代償）。
- Implicit Grant のトークンは約60日で失効する。再ログインが必要。
- ログインしない場合、Helix を叩けないため相手の配信タイトル・カテゴリ・
  アイコンは出ない。リンクと名前と人数だけになる。
- 公式シャウトアウトは自分が配信中でないとAPIが400を返す。

## 検証済みの内容

- `node --check` による構文チェック
- `parseTags` / `fmtWait` / `targetWait` / `globalWait` のユニットテスト
  （実際のraid USERNOTICE行、resub・cheerの除外、制限の境界値）
- ブラウザ実機での IRC行 → カード描画 → 履歴 → お礼文生成 の通し確認
- Twitch IRC への匿名接続の実接続確認
